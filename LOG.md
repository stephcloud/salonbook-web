# Log

## 2026-10-10

- Vercel deployed: https://salonbook-web-theta.vercel.app. `API_URL` is set for Production, Preview and Development, function region fra1, production branch `main`. The home page shows "API is awake".

- Dev-tool audit finding accepted for now: `npm audit` reports 9 high findings, all from one `braces` advisory (stack exhaustion on deeply nested patterns) reached through `fast-glob` in the shadcn CLI chain (`shadcn` -> `@shadcn/registry` / `ts-morph`) and in `eslint-config-next`. There is no patched `braces` release, and `npm audit fix` changes nothing. These are devDependencies used only on our machines and in CI at build and lint time, so they do not ship to users: `npm audit --omit=dev --audit-level=high` is clean. CI now blocks on that command and runs a plain `npm audit` as a non-blocking step so the findings stay visible. Revisit when `braces` has a fix.

- Auth and proxy built on `feat/auth-proxy`. The login handler stores the token in an httpOnly `sb_token` cookie (30 minutes) and returns only the user. `/api/proxy/*` adds the Authorization header, rejects `..` segments, blocks `auth/login` (it would return the token), clears the cookie on 401 and retries once. `/login` and `/register` (client or salon owner) exist, with `/salons` and `/dashboard` placeholders. Real API behaviour checked with curl: wrong password is 401 `{"detail":"invalid credentials"}`, bad register input is 422 with a `detail` list. POST and PATCH are not retried after a timeout, so a slow request cannot be applied twice. `maxDuration` is 300 on the new routes (Hobby ceiling with Fluid Compute); the existing home page still says 60.

## 2026-10-11

- Public salons built on `feat/public-salons`. `/salons` (list, 20 per page with Previous/Next because the API returns a bare array with no total) and `/salons/[id]` (details, services, stylists, Book links, copy salon link) are public: the four endpoints (`GET /salons`, `/salons/{id}`, `/salons/{id}/services`, `/salons/{id}/stylists`) need no token, checked against the live openapi.json. Server pages fetch through `publicGet` in `lib/api.ts` (no-store, one retry for the free-tier wake-up). Services and stylists use `limit=100`. A 404 or 422 from the API shows "Salon not found". Quote services show "Price on consultation"; the deposit is always shown. Photos are optional (gradient tile or initial avatar); owner images use `next/image` with `unoptimized`.

- Reviews of `feat/public-salons` done (code-reviewer twice, ui-reviewer once) and their findings fixed. Server-side public reads (`getSalons`, `getSalon`, `getSalonServices`, `getSalonStylists`) live in `src/lib/api-server.ts` so they cannot end up in the client bundle; `isMissingResource` (404 or 422 on a path id means "not found") stays in `src/lib/api.ts`. The detail page starts the services and stylists requests at the same time as the salon request, so a cold backend is hit once, not twice in a row. Only the salon request can produce "Salon not found"; a list failure shows the retry screen. A 502, 503 or 504 answer is retried once. The list promises carry a no-op catch so a missing salon cannot cause an unhandled rejection, and a test checks that.
- Dependencies changed with the owner's approval: added `clsx` and `tailwind-merge`, removed the `cn` package. `cn` is now defined in `src/lib/utils.ts` (`twMerge(clsx(...))`) and the shadcn components import it from there, so conflicting Tailwind classes resolve properly.
